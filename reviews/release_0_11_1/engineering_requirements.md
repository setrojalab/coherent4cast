# Engineering assessment of the 40-point attachment

Recorded 26 November 2026 for the 0.11.1 candidate. This is an internal source and evidence review, not an external professor's endorsement, a journal decision or a regulatory qualification. Numbering below follows the attachment's six sections. Candidate changes require the integrated package checks; historical 0.11.0 checks are not relabelled as checks of new code.

The attachment mixes useful contracts with new scientific methods, deployment controls, and guarantees that software alone cannot establish. The current maintenance decision remains one R/C++ statistical implementation, with Python accessing it through rpy2 or Rscript. This candidate does not introduce a second native Python distribution, parallel numerical implementation, new likelihood or changed uncertainty procedure.

Existing API/help describes their different interpretations. New confidence methods must preserve regularity gating; no numerical tolerance is described as a confidence interval. ## Python and performance changes in this candidate

`run_rpy2.py` now fits once by default, retains the R fit, and performs the second direct-R fit only with `--verify-parity`. CI enables that flag. `--timings` reports stage observations excluding imports/R initialization; no speedup has been measured or claimed. Both CSV routes preserve identifier text, including `001`, `1` and literal `NA`, and empty no-event labels. Help works before optional imports, missing dependencies and schema errors are actionable, and successful outputs explicitly state whether parity was requested.

The dedicated CI workflow exercises both bridge routes, label preservation, verification/default modes and invalid inputs. Local checks passed for Python/R syntax, pandas/R parsing, help, missing-dependency handling and workflow syntax. Full new rpy2 execution requires the candidate Linux CI run; historical 0.11.0 parity cannot replace it.

`R/fit.R:141` still evaluates the complete likelihood/score separately for optimizer objective and gradient calls. The archived four-parameter core benchmark has a shared-evaluation cache. A later optimization can cache identical evaluations, invalidating when quadrature/control changes, with explicit numerical parity tests. Native input copies likewise remain unchanged. The archived 8.11-second result concerns a fixed four-parameter core workload at 250,000 subjects; the 1.66-second high-level measurement is at 1,000 subjects. There is no demonstrated fastest-package or fastest-Python claim.

## Executed environment-diagnostic checks

The new R file was sourced into an environment whose parent was the installed 0.11.0 namespace from `COHERENTSURV_RELEASE_2026-11-25/build/coherentSurv.Rcheck`, using the local R-devel 4.7 toolchain and existing `Rlib47` dependencies. This tests the new utility against the maintained installed native engine; it is not a newly installed 0.11.1 package check. An initial R-release attempt could not load Rcpp from its default library; adding the existing matching toolchain/dependency library resolved the environment without installation or network access.

Observed maximum absolute errors were 1.11e-16 for the Poisson boundary, dense absorption and sparse absorption fixtures, and 2.66e-15 for the Louis mixture fixture. All are below the fixed 1e-12 tolerance. Operational status was `passed`; overall diagnostic status was `unavailable` because actual package compiler identity and build flags were not recorded. This is the intended distinction, not a failed numerical check.

All 64 focused expectations passed, and the new Rd file passed its syntax/content check. Testing also found that generated Rcpp RNGScope code can create a seed while entering deterministic native routines; the diagnostic now restores an existing RNG state or the original absence of one. The observed tiny-fixture elapsed values were below the R timer's resolution (reported as zero), and are not used to claim a speed advantage. BLAS identification was unavailable in this Windows runtime; LAPACK reported 3.12.1. Missing identification was retained instead of guessed.

The report does not sign itself, lock itself, certify a statistical computing environment, establish Part 11 compliance, prove a scientific model or measure production-scale performance. Native-file fingerprints identify bytes currently on disk, not historical compiler provenance or the identity of already loaded memory.
